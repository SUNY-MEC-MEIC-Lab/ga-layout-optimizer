# 한계 — 반드시 알고 쓸 것

[← README](../README.md) · [구조](ARCHITECTURE.md) · [결과 상세](RESULTS.md) · [벤치마크](BENCHMARKS.md) · [설치·연결](CONNECT.md)

> **NOT FOR CONSTRUCTION — 개념검토용.** 이 도구의 산출물은 시공·인허가 제출·상세설계에 그대로 쓸 수 없다.
> 모든 도면에 `NOT FOR CONSTRUCTION` 이 찍혀 나온다. 예제 파일의 치수·이격·제약 파라미터는 **전부 가정값**이며
> 실제 설계값이 아니다. 설계 책임은 유자격자에게 있고, **검토 대상은 도면이 아니라 IR** 이다.

## 모델과 엔진

1. **NOT FOR CONSTRUCTION.** 개념검토용이다. 예제의 모든 수치는 가정값이다.
2. **단일 외피 패킹이다.** 엔진은 건물 하나의 내부를 푼다.
   **다건물 부지배치(건물 간 배치)는 미구현**이다. 따라서 `SEISMIC-GAP` 은 구현·시험되어
   있지만 단일 건물 예제에서는 적용 대상이 없다. 부지배치는 계층분해 1단계의 상위 문제다.
3. **다층 관통부 정렬은 (v0.3 부터) 구조적으로 보장된다.** 위층 점유를 순열로 따로 배치하지 않고
   기준층 좌표를 고정 장애물로 박아 넣는다. 이전 버전에서는 페널티로 처리해 0.10 m 잔차가 남았다.
   `TALL-EQUIP` 은 여전히 검사하며, 지붕을 뚫는 기기는 Gate 1 이 ERROR 로 막는다.
4. **Sequence-Pair 패킹은 빈 공간을 만들지 않는다.**
   압축 배치가 항상 생성되므로, 큰 이격을 실현하려면 **그 사이를 채우는 실체**
   (통로·차폐벽·공지 블록)가 IR 에 명시되어야 한다. 없으면 최적화기는 페널티를 내고
   붙여 놓는 해를 낸다. 실제로 `examples/spec_minimal.json` 의 MS↔주제어실 12 m 이격은
   `SHIELD`(차폐벽 겸 통로) 블록을 넣기 전까지 어떤 seed 로도 만족되지 않았다.
   물리적으로도 그 12 m 는 빈 공간이 아니라 차폐벽이다 — **IR 이 현실을 덜 담고 있었던 것**이다.
   Gate 1 이 이 상황을 WARN 으로 알려준다(요구 이격이 어떤 단일 블록보다 클 때).
5. **거리는 직교/유클리드 대리모형이다.** 실제 배관 라우팅은 이보다 길다.
   원저자들도 이를 명시했다 — **편향의 방향을 알고 쓸 것.**
   실제 동선 기반 거리(Dijkstra)와 A* 라우팅 검증은 미구현이다. 피난 거리도 실 중심→계단 중심의
   직교거리로, 실제 보행거리의 하한이다.
6. **선량·차폐 계산이 없다.** 방사선구역 항은 순수 기하량(분산)이며 차폐비용의 대리지표다.
7. **IFC/BIM 출력이 없다.** 입력은 IFC 를 읽지만 출력은 DXF R12 까지다. 외부 라이브러리 의존을 추가하려면
   폐쇄망 설치 가능성을 먼저 확인해야 한다.
8. **기존 BIM 모델 편집 기능은 의도적으로 만들지 않았다.**
   BIM-Edit 벤치마크의 IFC 편집 작업 324개에서 최고 모델 평균 49.5%, **완전 해결 3.4%** 다.
9. **메타휴리스틱이므로 최적성 보증이 없다.** 갭을 보고할 수 있는 것은 정답이 공개된 벤치마크뿐이고
   (QAPLIB n=20~36 에서 최대 5.4%, Ejeh COGP 25기기에서 +39.6%),
   그것도 **탐색 기계장치**를 검증할 뿐 배치 목적함수의 정당성을 검증하지 않는다.
10. **진화·튜닝된 휴리스틱은 튜닝한 분포에만 맞는다.**
    FunSearch 가 진화시킨 빈패킹 휴리스틱은 다른 분포에서 Best Fit 보다 약 20배 나빴다.
    한 건물 유형·한 부지의 데이터로 튜닝한 배치 휴리스틱을 다른 유형에 그대로 쓰지 말 것.
    원자력에서는 NQA-1 의 **적용 범위(range of validity)** 정의 문제와 정확히 같다.

## 도면 인식

11. **도면 인식은 외접 사각형이다.** 직사각형이 아닌 실·기기는 외접 사각형으로 근사하고 경고한다
    (채움률 표시). 곡선 벽·사선 배치는 정확히 표현되지 않는다.
12. **PNG 는 문자를 읽지 않는다(OCR 없음).** 실 이름은 RM001… 로 붙고, 이름·용도는 사용자 답변으로
    IR 에 넣는다 (좌표가 아니므로 허용). 스캔·사진 도면은 벽선이 끊기면 실이 합쳐진다 — `close_gaps_px`.
13. **래스터 PDF 는 벡터로 읽히지 않는다.** CAD 가 선을 래스터처럼 출력한 PDF(공개 규제기관 문서 다수)는
    수십만 개 짧은 선으로 나와 실을 만들지 못한다 — 경고가 뜬다. PNG 로 변환해 넣을 것.
14. **빈틈없이 꽉 찬 평면은 Sequence-Pair 압축이 현황을 정확히 재현하지 못할 수 있다.**
    솔버는 현황 배치에서 출발(warm start)하지만, 결과가 현황보다 낫지 않으면 "현황 유지" 또는
    "채택 불가" 로 판정한다 — 개선을 지어내지 않는다 (병원·실제 도면 2건).
15. **가늘고 긴 실(형상비 5 이상)은 복도로 보고 구간으로 나눈다** (면적 보존). 복도 위치를 유지해야
    하면 해당 구간을 고정(`pinned`)하거나 `split_corridors: false` 로 만든다.
16. **현황 비교의 공정성은 IR 에 달려 있다.** 도면에는 연결·구역·이격 요건이 없다. 요건 없이
    줄이면 현황보다 '나쁜' 배치가 작게 나올 수 있다 — 그래서 도구가 질문을 먼저 한다.
    '어떤 실끼리 가까워야 하는가'(진료 동선 등)는 기능 유지 요건에 아직 없다 — 출입·연결·피난만 지킨다.

## LLM 과 데이터

17. **LLM 등급 분류.** 이 도구의 LLM 부분은 **비안전등급 생산성 도구**다.
    비결정론적이고 버전마다 출력이 바뀌는 LLM 을 안전등급 설계계산 도구로 지정(dedication)하는
    것은 현 실무상 불가능에 가깝다. 출력은 100% 사람과 결정론적 도구의 검증을 거쳐야 한다.
18. **로컬인 것은 엔진뿐이다.** Claude Code 의 LLM 레이어(요구사항 추출·해설)는 대화 내용이
    외부 상용 API 로 전송된다. **실제 설계값(치수·차폐·배치·보안)을 LLM 대화에 입력하지
    말 것 — 공개값·가정치만 허용한다.** 실데이터 적용은 폐쇄망 LLM(자체 호스팅) 경로가 필요하다.
    원격 MCP(ChatGPT 웹·Claude.ai)로 연결하면 도구 응답까지 해당 서비스로 간다.
19. **요건 수치 중 일부는 가정값이다.** 유료 기준(CCPS, NORSOK, ISO 15544, DNV, FGI 최신판)은 원문을 확인하지 못해
    예제 요건 파일에 "가정" 이라고 적어 두었다. 실제 적용 전 원문 대조가 필요하다.

## 원전 도메인에서 추가로

20. **국내 규정 조문 대조 미완.** KINS 심사지침은 NUREG-0800 SRP 와 동일 장·절 체계이므로
    대조 가능하지만, 원문 대조가 완료되지 않았다. 조직 표준 확정 전에 반드시 대조할 것.
21. **원전 사례는 합성 도면뿐이다.** 공개 원전 평면도는 비공개 처리되었거나 래스터여서 실제 도면 시험을 하지 못했다
    ([결과 상세](RESULTS.md) 3절).

## 실제 적용 전에 필요한 것

- 실제 기기·실 목록과 치수 (예제는 전부 가정값)
- 건축·배관 단가 — 원가 효과를 말하려면 필요하다
- 실 간 인접·동선 요건 — 실제 평면의 동선 구조를 지키려면 먼저 정의해야 한다
- (원전) IEEE Std 384 최신판 — `ELEC-SEP` 파라미터가 이것 없이는 채워지지 않는다
